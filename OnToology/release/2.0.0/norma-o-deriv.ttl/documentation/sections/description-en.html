NORMA-O Derivation module: Description back to ToC

The module describes derived normative graphs: the derivation activity, the rule set and version applied, the assumptions the conclusions depend on, and the prevalence orderings, norm evaluations and cycles they contain.

Scope

  • the activity that produced a derived graph, its inputs, rule set and output graph;
  • the non-monotonic assumptions under which its conclusions hold;
  • prevalence orderings, static or per case, and the level of each norm in them;
  • the applicability of each norm in a described case, and the parties it reaches;
  • cycles in the prevalence graph and their legal reading.

The conclusions themselves, such as the deontic closure, legal positions or relations between norms, are stated with NORMA-O terms (norma:entailsObligatory, norma:Duty, norma:deonticallyContradicts, norma:WeakPermission…). This module adds only what is specific to a derivation.

Asserted and derived graphs

A derived graph is regenerated, never maintained. It should be written to a named graph of its own (normad:derivedGraph) and never merged back into the annotation graph: otherwise a conclusion that stops following from the annotations, for instance after an exception is added, would remain as if it were annotated fact. normad:DerivationActivity is distinct from norma:AnnotationActivity, which produces annotations from legal sources; a derivation consumes annotations and produces their consequences. Two runs that report the same normad:ruleSetVersion over the same inputs are expected to produce the same graph.

Applicability statuses

Evaluating a case assigns each norm one status, in order of precedence:

StatusMeaning
normad:InvalidNot a member of the normative system: superseded, not yet in force, or repealed. It concerns validity, so it does not depend on the case.
normad:NotActivatedValid, but none of the trigger events that activate it fires in the case.
normad:ApplicableValid and activated, and every defeater reaching it is itself defeated, or none reaches it.
normad:DefeatedValid and activated, but an applicable norm defeats it.
normad:UndecidedThe asserted defeaters do not fix a label: the grounded fixpoint leaves the norm open.

The last three come from Dung's grounded labelling, a monotone fixpoint over the valid and activated norms. A norm is Undecided only when that fixpoint leaves it open: lying on a cycle is not enough, since a cycle attacked from outside is still decided. Repeal is applied flatly, before the ordering, so a repealed norm is not revived when its repealing norm is itself repealed (as in art. 2.2 of the Spanish Civil Code), whereas a norm set aside by an exception is reinstated when the exception falls. The scheme is about applicability, not being in force: whether a norm is in force is a matter of temporal validity; whether it reaches a case is what evaluation decides.

Prevalence orderings and cycles

A normad:PrevalenceOrdering without normad:forFactPattern is the static ladder over the whole normative system: its evaluations carry a level but no status. An ordering for one case keeps only the defeaters whose gating trigger events fire in it. The normad:prevalenceLevel of a norm is 0 if nothing prevails over it, and otherwise one more than the highest level among the norms that prevail over it. It is computed by longest-path layering on the condensation of the graph into strongly connected components, so every norm gets a level and the norms of one cycle share theirs.

Full acyclicity cannot be expressed in OWL 2 DL, so cycles are found by computation and reported, not resolved. Each normad:PrevalenceCycle is classified by the defeat that forms it:

Cycle kindWhen
normad:SecondDegreeConflictConflict defeaters on the cycle cite different resolution principles, so the criteria themselves are unordered for that pair (Bobbio).
normad:AnnotationContradictionConflict defeaters cite the same principle in opposite directions, which one principle cannot sustain.
normad:IrresolubleAntinomyThe defeat cites no principle at all, typically a loop of exceptions.

Assumptions

A derived conclusion is only meaningful together with the readings it rests on. Every normad:DerivationActivity declares at least one with normad:computedUnderAssumption:

AssumptionReading
normad:ClosedGraphA norm absent from the graph is absent from the normative system.
normad:ClosedCaseDescriptionA condition the case is silent about does not hold.
normad:DefeatConsideredDefeat relations were taken into account.
normad:DefeatNotConsideredDefeat relations were ignored; mutually exclusive with the previous one.
normad:GroundedSemanticsDefeat was evaluated under Dung's grounded semantics.
normad:ReinstatementNotComputedDefeat was applied one level deep, without reinstatement.
normad:InstitutionalFactsChainedFacts established by applicable constitutive rules were fed back into the case.
normad:OpenCounterpartyA counterparty no annotator named is read as not disagreeing when norms or positions are compared.

The reference rule set always declares ClosedGraph, ClosedCaseDescription, DefeatConsidered and GroundedSemantics; it adds InstitutionalFactsChained when the graph uses norma:establishesTrigger, and OpenCounterparty when some norm with an action names no counterparty. DefeatNotConsidered and ReinstatementNotComputed are available to other producers.

Example

Evaluation of Article 16 of the AI Act in a case where Acme substantially modified a high-risk system

:derivation_01 a normad:DerivationActivity ;
    normad:ruleSetVersion "norma-derivation/1.0" ;
    normad:computedUnderAssumption normad:ClosedGraph, normad:ClosedCaseDescription,
        normad:DefeatConsidered, normad:GroundedSemantics, normad:OpenCounterparty .

:ordering_Case_acme_modified a normad:PrevalenceOrdering ;
    normad:forFactPattern art25:Case_acme_modified ;
    prov:wasGeneratedBy :derivation_01 .

:ordering_Case_acme_modified_eval_OBL_Art16_provider a normad:NormEvaluation ;
    normad:evaluatedNorm art25:OBL_Art16_provider ;
    normad:inOrdering :ordering_Case_acme_modified ;
    normad:prevalenceLevel 0 ;
    normad:hasApplicabilityStatus normad:Applicable ;
    normad:reachesParty art25:Party_Acme .

Article 16 is addressed to the role provider; the case assigns Acme to that role under Article 25(1)(b), so the obligation applies and reaches Acme. The activity declares OpenCounterparty because the obligation names no counterparty. This is the output of the reference rule set on its test fixture test-roles-art25.ttl.

Reference rule set

NORMA-O provides a reference implementation (rule set version norma-derivation/1.0) that writes its output with this module. It consists of 19 SPARQL CONSTRUCT rules for action negation, the deontic closure, defeat edges, weak-permission candidates, Hohfeldian positions and relations between norms, and a Python implementation of the prevalence ordering: layered topological order (Kahn), strongly connected components for cycle detection, the levels on the condensation, and Dung's grounded labelling. Per case, evaluation alternates with counts-as chaining until no new institutional fact appears. It is checked by 140 automated tests, including consistency under HermiT.

pip install -r release/2.0.0/deriv/requirements.txt
python release/2.0.0/deriv/derive.py my-norms.ttl my-cases.ttl -o derived.ttl

Besides the derived graph, the rule set warns about what it cannot resolve or what looks wrong in the annotation: prevalence cycles, defeats against Strict norms, norms outside the system, role assignments whose justifying rule does not apply, and norms without a counterparty or a norma:LegalAction.

Intended use

The module is intended for anyone who publishes or consumes conclusions computed from NORMA-O graphs: compliance tools that answer which norms apply in a case, research comparing derivation semantics, and audits that need to know how a result was obtained. Producers using other semantics should declare the assumptions that match their reading, and may add new normad:Assumption values to the scheme.
